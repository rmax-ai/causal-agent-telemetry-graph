# ADR-005 — No Raw Evidence in System Instructions

- **Status:** Accepted (SPEC.md §7)
- **Source:** SPEC.md §7 (ADR-005), §3 (Dominant Constraints), §14 (Detector Restrictions), §18 (Threat Model — detector prompt injection), §19 (Experiment 3), §25 (Acceptance Criteria); AGENTS.md (non-negotiable rule 3)

## Context

CATG ingests adversarial imported data: poisoned tool results, malicious MCP servers, and detector-directed prompt-injection attacks are modeled threats (SPEC.md §18, §19 Experiment 3 attack classes). If untrusted evidence content were concatenated directly into privileged detector instructions (system prompts), an attacker who controls tool output or message content could redirect detector behavior — the "detector prompt injection" threat (SPEC.md §18). The stated constraint is explicit: "Never inject raw evidence directly into privileged detector instructions" (SPEC.md §3).

## Decision

**Untrusted content is never concatenated into privileged detector instructions; it is passed as delimited data** (SPEC.md §7 ADR-005; AGENTS.md non-negotiable rule 3).

- Detectors receive **immutable evidence references** and structured evidence packages, never writable source events (SPEC.md §14).
- Evidence packages are structured JSON (intent, principals, agents, authority, untrusted inputs, sensitive paths, effects, policy decisions, unknowns) — never free-text concatenation of untrusted tool output (SPEC.md §14; AGENTS.md "Content Security").
- Detector evidence content is treated as untrusted data; detectors validate output against a strict schema and run with network/tool access disabled unless explicitly allowed (SPEC.md §14, §18).
- Experiment 3 measures isolation conditions: direct concatenation vs delimited envelope vs untrusted excerpts separated vs hash/reference-first retrieval vs deterministic rules + semantic escalation (SPEC.md §19).

## Consequences

### Positive

- Detector-targeted prompt injection is structurally harder: untrusted content is data, not instructions (SPEC.md §18, §25 — "detector evidence separated from privileged instructions").
- Findings remain traceable to immutable evidence references (SPEC.md §14, §17).
- The isolation experiment produces measurable attack-success rates per condition (SPEC.md §19).

### Negative / Constraints

- Detector prompts must be designed around delimited evidence structures, which costs prompt complexity (SPEC.md §14).
- Some attacks (e.g., poisoned policy descriptions, forged provenance, fake evidence IDs) still require defense in depth — redaction, hashing, and validation remain necessary (SPEC.md §19).

### Neutral

- Evidence packaging becomes a first-class pipeline stage (Evidence Package Builder, SPEC.md §7, §14).
