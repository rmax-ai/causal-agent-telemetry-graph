# ADR-003 — Deterministic Policies Before Semantic Detectors

- **Status:** Accepted (SPEC.md §7)
- **Source:** SPEC.md §7 (ADR-003), §13 (Policy Engine), §14 (Detector Framework), §19 (Experiment 2), §5 (Adopted from ADR); ARCHITECTURE.md §5.8–§5.9

## Context

CATG must detect security violations in agent workflows with reproducible, explainable results at bounded model-token cost. Uber ADR's detector pattern is fast/cheap triage followed by deeper context-aware reasoning (SPEC.md §5). The project tracks cost and latency as first-class metrics (SPEC.md §5, §22) and requires reproducibility — deterministic replay of policy decisions must not mutate original decisions (SPEC.md §21). Semantic detectors are expensive, non-deterministic across model versions, and themselves a target of prompt injection (SPEC.md §18, §19 Experiment 3).

## Decision

**Deterministic graph policies execute before semantic detectors: rules first, reducing cost and improving reproducibility** (SPEC.md §7 ADR-003).

- The policy engine evaluates compiled YAML policies (Zod-validated, deliberately constrained grammar) against the projected graph and returns ALLOW/DENY/REQUIRE_APPROVAL/FLAG/INDETERMINATE, materializing a `PolicyDecision` (SPEC.md §13).
- Six required policies are specified (SPEC.md §13): credential exfiltration, production mutation approval, delegation attenuation, restricted data to untrusted MCP, premature approval invalidity, authorization scope mismatch.
- Semantic detectors (transcript LLM, graph-summary LLM, deterministic graph rules, retrieval-assisted investigator, hybrid cascade) run after, consuming immutable evidence references under strict output validation (SPEC.md §14).
- Experiment 2 measures the cascade: rules only, rules + semantic escalation, triage + deeper reasoning — target ≥ 40% reduction in semantic-model calls while preserving ≥ 95% recall (SPEC.md §19).

## Consequences

### Positive

- Cheap deterministic rules answer many security questions without model cost (SPEC.md §5, §19).
- Decisions are deterministic and replayable: same evidence → same decision, with policy digest + evidence IDs on every decision (SPEC.md §13; ROADMAP Phase 3 acceptance).
- Semantic detectors are reserved for cases rules cannot decide, reducing attack surface and token cost (SPEC.md §14, §19).

### Negative / Constraints

- The policy grammar must stay deliberately constrained to avoid "reinventing Rego" (SPEC.md §24 risk).
- Policies cannot express everything; unresolved cases still escalate to semantic detectors, which must run sandboxed (SPEC.md §14, §18).

### Neutral

- Note: SPEC.md §1 states "five deterministic policies" while §13 enumerates six; the required set follows §13's six-policy list (ARCHITECTURE.md §1 flags the same discrepancy).
