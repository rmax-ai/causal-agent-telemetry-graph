# ADR-002 — Typed Property Graph, Not RDF Runtime

- **Status:** Accepted (SPEC.md §7)
- **Source:** SPEC.md §6 (Standards and Literature Foundations — PROV), §7 (ADR-002), §8 (Domain Ontology), §11 (Storage Design); ARCHITECTURE.md §6

## Context

CATG needs provenance and causation semantics. W3C PROV-DM/O is the natural conceptual foundation, and CATG adopts it: Entity/Activity/Agent, and usage, generation, derivation, association, and delegation relations (SPEC.md §6). However, the project constraints are a research-grade **TypeScript** monorepo (SPEC.md §1, §20), embedded local storage with no external graph service (SPEC.md §3, §7), and graph-path investigation as the primary read pattern (SPEC.md §11 — Kuzu "Path traversal and investigation"). An RDF/OWL runtime would add a serialization and inference stack with no direct payoff for those constraints.

## Decision

**Use a typed property graph specializing PROV semantics — no RDF/OWL runtime** (SPEC.md §6 "Deliberate Non-Alignment: No RDF/OWL runtime"; SPEC.md §7 ADR-002 "Specialize PROV semantics in property graph for TypeScript ergonomics").

- The ontology is a typed registry: 28 node types / 27 edge types with universal fields, confidence, and provenance metadata (SPEC.md §8).
- PROV concepts map onto graph constructs: e.g., `USED`/`READ_FROM` specialize `used`; `GENERATED`/`WROTE_TO` specialize `wasGeneratedBy`; `DERIVED_FROM` = `wasDerivedFrom`; `ACTED_ON_BEHALF_OF`/`DELEGATED_TO` = `actedOnBehalfOf`; `INFORMED_BY` = `wasInformedBy`; `INITIATED` = `wasAssociatedWith` + CATG role; `CAUSED` is a qualified workflow-causation assertion (SPEC.md §6).
- The projection is stored in embedded Kuzu as typed relationship tables plus a generic `ASSERTS` relation for rare edge types (SPEC.md §11).

## Consequences

### Positive

- TypeScript ergonomics: node/edge types map directly to Zod schemas and inferred TS types in `packages/schema` and the ontology registry in `packages/graph-model` (SPEC.md §20).
- No RDF stack to run, serialize, or reason over — consistent with the one-command local setup (SPEC.md §3).
- Typed edges carry confidence, causalBasis, evidenceIds, and linkerVersion natively (SPEC.md §8).

### Negative / Constraints

- PROV compatibility is conceptual, not machine-verifiable: no RDF/OWL inference or SPARQL-style query surface exists (SPEC.md §6 "Deliberate Non-Alignment").
- Generic/rare edge types must fall back to the `ASSERTS` relation in Kuzu, losing some typing (SPEC.md §11).

### Neutral

- The PROV mapping must be maintained manually as the registry evolves; the mapping table in SPEC.md §6 is the reference.
